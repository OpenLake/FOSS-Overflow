# Project Idea 💡

Leaderboard Pro is a platform built to bring together competitive programming and coding profile data from different platforms into one place. It helps users compare rankings, view analytics, track progress, and understand their coding journey better through a single dashboard.

# My Contributions 💻

During my contribution, I worked mainly on the analytics and leaderboard experience of the project.

- Built and improved unified analytics logic for combining scores from platforms like LeetCode, Codeforces, CodeChef, and GitHub
- Worked on backend API views for analytics and trend-based data
- Helped fix frontend rendering issues in the leaderboard and analytics flow
- Debugged data handling issues caused by Pandas conversions and scoring logic
- Fixed JSX structure issues in routing so the frontend pages render correctly
- Improved error handling in analytics-related views to make failures cleaner and easier to debug
- Reviewed the feature end to end, from API response generation to frontend rendering

One of the biggest challenges was debugging issues that were not obvious at first glance. Some bugs came from edge cases in ranking data, while others came from frontend route structure and integration between backend and frontend. This taught me how important careful end-to-end debugging is in real projects.

# What I gained 📈

This contribution helped me grow both technically and personally.

- Improved my Django development skills by working with views, models, and backend logic
- Learned more about Django REST Framework and how APIs are designed and consumed in a real project
- Got better at debugging full-stack issues across backend and frontend
- Improved my understanding of data handling, normalization, and ranking logic
- Learned how to read stack traces more confidently and trace issues to the actual source
- Practiced working with React components and route-level rendering issues
- Improved collaboration skills by understanding mentor feedback and refining code based on review comments
- Learned the importance of secure error handling and not exposing internal backend details directly

# Experience ✌️

My experience contributing to FOSS Overflow through this project was genuinely valuable. It gave me a chance to work on a real open-source codebase where even a small issue could affect multiple parts of the project. I got to understand how real collaboration works, how code reviews push us to improve, and how much learning happens through debugging.

At times, the issues felt difficult, especially when the bugs involved multiple files or depended on environment setup. But solving them step by step gave me more confidence as a contributor. I also realized that open source is not just about writing code, but about understanding systems, communicating clearly, and improving with feedback.

Overall, this contribution was a meaningful learning experience for me, and it helped me become more comfortable with Django, REST APIs, debugging, and contributing to a team project.
